# 4-3 · MCMC 的核心直覺

> [!question] 本卡核心問題
> 你知道 MCMC 是「派機器人在山上走」。**但機器人怎麼走才對?**
>
> - 「讓足跡密度 = 後驗」要怎麼保證?
> - 為什麼 MCMC **不需要算 $p(D)$**?
> - 1953 年的 Metropolis-Hastings 為什麼到現在還是基礎教材?

---

## ① 直覺鋪墊:兩個極端都失敗

目標:機器人的足跡密度要等於山的高度(山高的地方踩多、山低的地方踩少)。

| 策略 | 結果 |
|---|---|
| **完全隨機亂走** | 足跡**均勻分佈**整座山,完全不反映形狀 ❌ |
| **永遠往山頂爬** | 最後**卡在山頂不動** ❌ |

**正確策略**:**「往高處走容易,往低處走有時候允許,但有條件」**

> 🔑 **核心直覺**:
> - 機器人**傾向**往機率高的地方走(留下多的足跡)
> - 但**偶爾**也要往機率低的地方走(才能採到山的尾巴)
> - **「走的頻率」要正比於「山的高度」**

這個平衡的精確數學描述,叫**細緻平衡條件**。

---

## ② Metropolis-Hastings:規則只有兩步

### 🤖 演算法

每一步,從目前位置 $\theta^{(t)}$:

**步驟 1 · 提議(Propose)**
從提議分佈隨機選一個候選 $\theta'$。最常見:$\theta'\sim\mathcal{N}(\theta^{(t)},\sigma^2)$(在附近隨機跳一步)。

**步驟 2 · 接受/拒絕(Accept/Reject)**

$$\alpha = \min\left(1,\;\frac{p(\theta'\mid D)}{p(\theta^{(t)}\mid D)}\right)$$

擲一個 $[0,1]$ 均勻骰子 $u$:
- $u < \alpha$ → **接受**,$\theta^{(t+1)} = \theta'$
- $u \ge \alpha$ → **拒絕**,留在原地

**就這樣。重複幾千次幾萬次。**

### 🖼️ 直覺解析

```
      後驗山:
          _∩_
         /   \_
       _/      \_
      /          \
     ────●─────●────────  θ
         舊      新
         (低)    (高)     ← 上山:α = 1,一定接受

     ────●─────●────────  θ
         舊      新
         (高)    (低)     ← 下山:α = p(新)/p(舊) < 1
                              機率性接受,有時候會拒絕
```

- **往上走** → $\alpha = 1$,**一定接受**
- **往下走** → $\alpha < 1$,**機率性接受**(下山幅度越大越可能被拒絕)

> 🔑 **這個規則的精神:熱衷往高處走,但不堅決。** 下山的可能性開了一個口,讓機器人能採到山的尾巴和谷底。

### 為什麼下山也要允許?

> **如果機器人從不下山,它會卡在山頂不動 —— 你完全不知道山底和山腰長什麼樣子。**
>
> **工程後果**:沒採到後驗的尾巴和低密度區域 → **可信區間會過度狹窄,系統過度自信**。

### 🎯 這是「探索 vs 利用」的權衡

> 🔑 **MCMC 機器人面對的是 Exploration vs Exploitation**:
> - **純利用**(只往高處走) → 卡在山頂,完全沒採到形狀
> - **純探索**(隨便亂走) → 散得到處都是,完全沒反映形狀
> - **平衡**(MH 接受規則) → 「比舊位置低的地方有時候去,但去的頻率正比於那個位置的機率」
>
> **這個權衡會在 [[7-2_貝葉斯最優化]]、強化學習、MCTS 反覆出現。**

## ③ 揭開祕密:為什麼不需要 $p(D)$?

$$\alpha = \frac{p(\theta'\mid D)}{p(\theta^{(t)}\mid D)} = \frac{p(D\mid\theta')p(\theta')\,/\,\cancel{p(D)}}{p(D\mid\theta^{(t)})p(\theta^{(t)})\,/\,\cancel{p(D)}} = \frac{p(D\mid\theta')p(\theta')}{p(D\mid\theta^{(t)})p(\theta^{(t)})}$$

🎉 **$p(D)$ 消失了!**

> 🔑 **MCMC 永遠在計算「兩個位置的相對機率」(比值),從不計算「絕對機率」。**
> **而比值會自動消掉歸一化常數 $p(D)$。**

### 對照三種繞過 $p(D)$ 的方式

| 方法 | 怎麼繞? | 代價 |
|---|---|---|
| **Laplace** | 用 MAP + Hessian 近似,假裝是高斯 | 犧牲精度換速度 |
| **VI** | 用 ELBO 把 $p(D)$ 變成下界 | 犧牲精度換速度 |
| **MCMC** | **用比值直接消掉** | **不犧牲精度,但要花時間採樣** |

> 💡 **三種方法本質上都在繞 $p(D)$,只是繞的方式不同。MCMC 繞得最乾淨。**

---

## ④ 為什麼這樣走會「正確」?細緻平衡

把後驗想成**水流分佈** —— 機率高的地方水多。

**細緻平衡條件**:任意兩個位置 A、B 之間,水流是平衡的:

$$\underbrace{p(A)\,P(A\to B)}_{\text{從 A 流到 B}} = \underbrace{p(B)\,P(B\to A)}_{\text{從 B 流到 A}}$$

如果每一對位置之間都平衡,**整體系統沒有淨水流** → 系統處於平衡態,**而這個平衡態剛好就是後驗分佈**。

### MH 怎麼滿足?

假設 $p(B) > p(A)$:
- $\alpha(A\to B) = 1$
- $\alpha(B\to A) = p(A)/p(B)$

驗證:
$$p(A)\cdot 1 = p(A) \qquad p(B)\cdot\frac{p(A)}{p(B)} = p(A)$$

**兩邊相等** ✅

> 🔑 **MH 的接受規則就是設計來自動滿足細緻平衡的** —— 它的數學保證了「足跡密度最終會逼近後驗」。

## ⑤ 工程痛點:走得對 ≠ 走得快

| 痛點 | 說明 | 解法 |
|---|---|---|
| **自相關高** | 每步從附近跳,連續樣本高度相關。1000 個樣本可能只等效 50 個獨立樣本 | 算 **Effective Sample Size (ESS)** |
| **步長難調** | 太小 → 接受率 95%+ 但走不動;太大 → 接受率 5%,卡原地 | **目標接受率 23%–44%** |
| **高維極慢** | 1 維表現好,100 維幾乎走不動 | 用 **HMC / NUTS** |

### 現代 MCMC:HMC 和 NUTS

**HMC(Hamiltonian Monte Carlo)**:把後驗想成**重力地形**,給機器人一個隨機初速度,讓它沿地形**滾動**一段時間。

物理直覺:**Hamilton 力學的能量守恆** —— 機器人滾動時會自然沿著等高線走,**不浪費步伐**。它用了梯度資訊,所以高維時遠快過 MH。

**NUTS(No-U-Turn Sampler)**:HMC 的自動化版本,自動決定滾多久。**這就是 Stan 和 PyMC 內建的引擎**。

## ⑥ 隱藏陷阱:雙峰後驗會卡住

```
         ▲              ▲
        / \            / \
       /   \          /   \
      /     \________/     \
     ─●──────────────●─────────  θ
      峰1            峰2
   (機器人在這)
```

機器人卡在峰 1。要跳到峰 2,**必須先穿過低谷** —— 但低谷的後驗很低,提議**幾乎全部被拒絕**。

> 🚨 **結果:機器人永遠走不到峰 2,即使採樣 100 萬次。**
>
> **而且 trace plot 看起來很正常 —— MCMC 不會主動告訴你它沒收斂。**

### 救援方法

| 方法 | 做什麼 |
|---|---|
| **多鏈 MCMC** | 從不同起點跑多條鏈,看是否收斂到同一分佈($\hat R < 1.01$) |
| **Parallel Tempering** | 同時跑多個「溫度不同」的鏈(高溫跳得遠、低溫跳得準),互相交換位置 |
| **改變參數化** | 用變數變換讓兩個峰靠近 |

> 🔑 **MCMC 的「漸近無偏」是真的,但「漸近」可能等到地老天荒。**
> **這就是為什麼工程上 VI 仍有它的位置。**

## ⑦ 採樣派的三大失敗模式(總結)

| 失敗模式 | MCMC | Particle Filter |
|---|---|---|
| **跨不過低谷** | ❌ 嚴重(單鏈序列採樣,當前位置強相關) | ✅ 較不怕(**粒子並行**,天生分散在不同峰) |
| **樣本多樣性喪失** | 自相關高 | **粒子坍塌** → 用**重採樣**救 |
| **高維詛咒** | 接受率指數下降 | 粒子數需指數成長 |

### 為什麼 PF 比較不會卡在一個峰?

> 🔑 **機制不同**:
> - **MCMC 是「序列採樣」** —— **一個**機器人沿時間走出足跡,當前位置和上一步強相關,所以「卡住」是因為跳不出去
> - **PF 是「並行採樣」** —— **一群**粒子同時在不同地方,**獨立演化**,所以即使中間有低谷,粒子也能「分頭活在各自的峰」

```
雙峰後驗:
         ▲              ▲
        / \            / \
       /   \          /   \
      /     \________/     \
     ─●──●───●──●───●──●─●─
      PF 視角:粒子天生分散在各處
      MCMC 視角:只有一個 ●,卡在某一峰
```

**但 PF 也有自己的痛點**:
- **粒子坍塌**:跑久了大部分粒子權重接近 0 → 定期**重採樣**恢復多樣性
- **高維詛咒**:粒子數需隨維度指數成長 → PF 在 >30 維就跑不動(所以深度學習不用 PF,但機器人/SLAM 大量使用)

## 🔗 回頭連結

| 你已學過的 | 在 MCMC 的位置 |
|---|---|
| **Monte Carlo 積分** | MCMC 是它的「序列版本」,有時間相關性 |
| **Particle Filter** | SMC,採樣精神類似但專為動態系統設計 |
| **隨機梯度下降** | 也是隨機的位置更新,但目標是優化不是採樣 |
| **探索 vs 利用** | MH 接受規則的精髓,會在 RL、貝葉斯最優化再出現 |

## 🎓 費曼檢驗

### 問題 1
為什麼 MCMC 的接受機率裡 $p(D)$ 會消失?這如何讓它在「不可能任務」上找到捷徑?

> [!success]- 參考答案
> **因為 MCMC 計算的是兩個位置的「相對機率」(比值),不是絕對機率。** $p(D)$ 對所有 $\theta$ 都一樣,在分子分母上下消掉。
>
> **為什麼是捷徑**:$p(D) = \int p(D\mid\theta)p(\theta)d\theta$ 在高維算不出來,是貝葉斯計算的萬惡之源。各派繞法不同:
> - MAP:不需要歸一化
> - Laplace:假裝不需要它
> - VI:巧妙地把它變成下界
> - **MCMC:不算它,讓它消掉** ← 最乾淨的招數
>
> 💡 **「能不能繞掉歸一化常數」是判斷一個方法是否可行的關鍵問題** —— 你以後讀論文會不斷遇到。

### 問題 2
「上山一定接受、下山有條件接受」—— 各自為什麼合理?如果從不下山會怎樣?

> [!success]- 參考答案
> - **上山一定接受**:新位置的後驗比舊位置高,往那裡走是對的。
> - **下山要有條件**:如果從不下山,機器人會**卡在山頂不動**,你完全不知道山底和山腰長什麼樣。但也不能無條件下山(那就變成亂走)。**接受機率正比於高度比,剛好平衡。**
> - **從不下山的後果**:沒採到後驗的尾巴和低密度區域 → **可信區間會過度狹窄,系統過度自信**。
>
> 🔑 這就是 **Exploration vs Exploitation** 的權衡 —— 它會在 RL、貝葉斯最優化、MCTS 反覆出現。

### 問題 3
Particle Filter 會不會也遇到「卡在一個峰」的問題?採樣派最怕什麼?

> [!success]- 參考答案
> **比較不會**,因為機制不同:
> - MCMC 是**序列採樣**(一個機器人沿時間走),卡住是因為從當前位置跳不出去
> - PF 是**並行採樣**(一群粒子同時在不同地方,獨立演化),所以即使中間有低谷,粒子也能分頭活在各自的峰
>
> **採樣派的三大失敗模式**:
> 1. **跨不過低谷**(MCMC 嚴重,PF 較輕)→ 多鏈、Parallel Tempering
> 2. **樣本多樣性喪失**(MCMC 自相關;PF 粒子坍塌)→ 重採樣、算 ESS
> 3. **高維詛咒**(兩者都有)→ HMC(用梯度)或改用 VI
